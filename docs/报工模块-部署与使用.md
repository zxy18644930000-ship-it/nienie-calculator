# 报工模块 · 部署与使用手册

> 一句话：工人在微信里扫码 → 选工序 → 现场拍照 → 填件数 → 提交；你（老板）在手机上随时看每人每天的产值，AI 帮你在照片上数数做异常预警。

模块和「捏捏乐算价」共用同一个小程序（AppID `wx315704667caab763`），不另外注册；算价功能不受任何影响。

---

## 一、一次性部署（约 15 分钟，照着做一遍）

**第 1 步 · 开通云开发**
微信开发者工具打开本项目（目录 `miniprogram/`）→ 点顶部「云开发」按钮 → 按提示开通（新账号有免费体验期，之后基础套餐 19.9 元/月，上线后 15 天开始计费）。
开通后复制「环境 ID」，填到 `miniprogram/config.js` 的 `ENV_ID` 里（留空则用默认环境，一般也行）。

**第 2 步 · 部署 6 个云函数**
左侧资源管理器展开 `miniprogram/cloudfunctions/`，对 `login`、`report`、`admin`、`countPhoto`、`summarize`、`calc` 这 6 个文件夹**分别右键 → 「上传并部署：云端安装依赖」**。
`countPhoto` 和 `summarize` 会问是否带定时触发器，选「允许」（一个每 5 分钟数照片，一个每天 23:58 生成快照）。`calc` 是算价数据的云端同步。

**第 3 步 · 一键初始化（建库 + 设管理口令 + 成为管理员）**
开发者工具里编译运行 → 你会被自动带到「报工」首页 → 点底部**「管理员入口」** → 输入你想设的管理口令（至少 4 个字，**记牢它**）。
第一次会提示「初始化完成」：5 个数据库集合自动建好、配置写好、你这台设备已是管理员。
⚠️ 请在把二维码发给工人**之前**先做这一步（谁先输口令谁成为管理员）。

**第 4 步 · 确认**
重新编译一次 → 你应该直接看到算价页，顶栏多一个「报工」按钮（工人则永远进不了算价页）。
再花 30 秒改一个存储权限（否则你看不到工人拍的照片）：云开发控制台 → 存储 → 权限设置 → 选「**所有用户可读，仅创建者可读写**」→ 保存。

**第 5 步 · 录工序**
报工首页 →「管理」→「工序管理」→「＋新增工序」，把「内包装 / 外包装 / 画画」和各自的单价（元/件）加上。以后改价、停用也在这里。

**第 6 步 · 让工人用起来**
- **工人 ≤ 10 人**：mp.weixin.qq.com 后台 → 成员管理 → 把每个工人的微信号加为「体验成员」→ 按老流程发布（开发者工具「上传」→ 后台「版本管理」把开发版本设为体验版）→ 把体验版二维码发到工人群。
  （体验版是个人主体，最多 10 个体验成员、5 个开发者，这是微信的限制。）
- **工人 > 10 人**：需要提交审核走正式发布（类目选「工具」，版本说明写「内部计件报工工具」），通过后任何微信扫码就能用。

## 二、工人怎么用（这段可以直接发群里）

1. 微信扫二维码打开小程序 → 先在入口页点「**报工时**」，第一次进来填一下自己的名字
2. 点你做的工序（比如「内包装」）
3. 对着**刚做完的这一批**拍一张照片（必须现拍，不能选相册里的旧图）
4. **选品类**——点开下拉框选（比如「汉堡捏捏乐」）
5. 填这批的数量（如果老板开启了 AI 核对，页面上会出现绿色的「AI 建议 XX 件」，和你数的一样就点一下填入）
6. 点「提交」——首页马上能看到自己今天做了多少件、今天的总金额；「我的记录」里能翻每一天和每张照片（**各工序单价和分项金额只有老板能看到，工人不显示**）

## 三、你每天怎么用

- **打开小程序先选入口**：「报工时」或「计算器」。你这台 iPad 已经开通老板权限，点计算器直接进；**手机或新设备第一次点计算器会弹口令框——输入你当初设的管理口令（见第 3 步），这台设备就开通了**，以后直接进。
- **订单记录已跨设备汇总（单价各机独立）**：任何一台设备存的单都会汇总到同一份记录里——记录页顶部有 **总单数 / 总金额 / 各设备各报多少单**，每单下面标着「来自 XX」。**商品单价和满减保持每台设备独立、互不影响**（按你的要求）。断网照常用，联网自动汇总。
- **报工首页**：点「当日汇总」看每人今天的件数和产值——每行还带 **AI 对账**：自报 X 件 / AI 数 Y 件 / **差 Z 件**（红字）、多少钱，以及"N 条没数上"；点人名可以看每一条明细和照片（还能「复制汇总」发微信记账，也带对账）；明细里**长按一条可以删掉**——比如工人报错了。
- **异常复核**：只有 AI 数出的件数和工人报的件数偏差超过阈值（默认 30%）的记录才会出现在这里；你看着照片点「没问题」或「要核实」。**AI 只预警、不拦截**，工人报工永远不会被卡住。
- **工人管理**：改名字（帮工人纠错）、停用（有人走了点一下，他不能再报工，历史记录保留）。
- **单价/分项金额只有老板看得到，今日总金额本人可见**：工人端首页显示「今日总金额 + 总件数」，但工序单价、今日各工序的分项金额、「我的记录」里的金额、提交按钮金额都不显示（后端也不返回）。只有管理员（`wl_config.admin_openids` 里的微信号）看到 ¥单价、¥分项金额、¥每日金额。注意：如果某人当天只做一个工序，用「总金额 ÷ 件数」可以反推出该工序单价。
- **工序管理 / 品类管理**：报工的工序和单价在「工序管理」；报工第二步下拉框里的品名在「品类管理」——点一行改名、右边开关启停、**长按一行删除**（停用/删除都不影响已有记录）。
- 每天晚上 23:58 自动存一份当天快照（`wl_summary`），白天看到的汇总本来就是实时的。

## 四、AI 照片数数（已接入，当前按要求暂停）

**状态（2026-10-15 晚）：AI 自动数数已暂停**（`wl_config.ai.enabled = false`）——报工页不再出现「AI 建议」，当日汇总不再显示对账行，AI 相关的红字提示全部安静；**照片照常上传存档**，工人的「我的记录」、你的明细/复核都不受影响。
想恢复：云开发控制台把 `wl_config.ai.enabled` 改回 `true`（或让 Claude 调一下），模型和 Key 都留着没动。

当时接入的情况（恢复后的参考）：已接入 **MiniMax（模型 `MiniMax-M3.1-Flash-Preview`，原生多模态）**，Key 存在云函数 `countPhoto` 的环境变量 `VLM_API_KEY` 里（超时已调到 60 秒）。接入实测：12 件的照片 AI 数出 12 件，约 9 秒出结果。

- 工作方式：**报工时拍完照立刻数一遍，页面上直接给「AI 建议 XX 件」**（可点一下填入）；失败时有「**重数一次**」按钮；后台每 5 分钟自动补数（没数上的、连失败会回炉重试最多 4 次；「异常复核」页的「立即检查」可手动催，含重试判死的）。
- **多数投票**：每次数**两遍**（并行，等待时间≈一遍）；两遍不一致再数**第三遍**取多数，三个都不同取中间值；每次的票都记录在案（记录里的 `ai_votes`）。
- **对账定位**：AI 数是给老板算账用的——日报里每人的「自报 vs AI vs 差 X 件」；照片挤成一堆时模型只能粗估（人也难点清），**同一张照片在 ±1~2 件内抖动是正常的下限**（投票能压掉偶发的大偏差，压不掉 ±1）；差得多会进「异常复核」等你核对照片。想要数得准：拍照时把东西尽量**摆开一点**、**一张不超过 ~20 件（多了分两张拍）**。
- 换服务商/模型：改 `wl_config.ai` 里的 `base_url`/`model`（任何 OpenAI 兼容的多模态接口都行；备选：阿里百炼 `qwen-vl-plus`、智谱 `glm-4v-plus`、火山方舟）；Key 换到 `countPhoto` 环境变量。
- 关掉 AI：把 `wl_config.ai.enabled` 改成 `false` 即可。

**关于准确率和阈值**：自由拍的照片 AI 数不准是正常的（几十件一堆，误差 ±10~20%）。所以规矩是「只预警、不拦人」，`flag_ratio`（默认 0.3）是标红门槛——误报太多就调大（如 0.5），漏报再调小。照片本身的存档作用不依赖 AI（有照片就有底账可查）。

## 五、常见问题

| 现象 | 先查什么 |
| --- | --- |
| 页面报「云函数还没部署」 | 第 2 步 5 个函数是不是都上传成功了 |
| 报「云开发还没初始化」 | 还没做过初始化：点底部「管理员入口」输一次口令（第 3 步） |
| 管理口令忘了 | 云开发控制台 → 数据库 → `wl_config` → `main`，里面能看到和修改 `admin_pass` |
| 工人打开还是算价页 | 正常逻辑是秒跳到报工页；如果没跳，多半是云函数没部署（此时保持不动是故意的，算价页不受影响） |
| 照片传不上去 | 云存储没欠费 + 网络；开发者工具里拍照会用电脑文件选择框模拟，正常 |
| 想改「偏差多少才标红」 | 改 `wl_config.ai.flag_ratio`（0.3 = 30%） |
| 你在汇总/复核里打不开工人拍的照片 | 存储权限没放开：云开发控制台 → 存储 → 权限设置 → 「所有用户可读，仅创建者可读写」 |
| AI 建议数明显离谱（如几百几千） | 已修复过一次（提示词歧义+解析）；如再遇到，把那张照片和 AI 数字发给我，我按老办法取原图+原始输出排查 |
| AI 数和工人报的差挺多（尤其挤成一堆的照片） | 正常：密集堆叠模型只能粗估；差异大自动进「异常复核」等你核对照片。想数得准：拍照摆开一点 |
| 控制台「定时触发器」面板显示暂无数据 | **正常现象**：该面板只登记控制台自己创建的触发器，用 `makeTriggers` 建的它不显示，不影响运行。判断定时器活着：看 `countPhoto` 的日志每 5 分钟自动有一条 |
| 怀疑定时器失效（日志不再自动出现） | 用 `makeTriggers` 重建（见第六章）：管理员身份调 `{"name":"wlCountPhotoTimer"}`、`{"name":"wlSummarizeTimer"}`；若返回"已经存在"说明其实还在 |

**其他说明**

- 工人手机里不会出现任何算价内容；报工页看不到工序单价/分项金额（只显示件数），首页只额外显示本人今日总金额；工人之间互相也看不到对方的记录（只有你和管理相关页面能看到全员）。
- 照片存在云存储 `wl_reports/日期/` 下，暂时不做自动清理（证据优先）；以后量大想省存储再加定期清理。
- 成本：云开发 19.9 元/月（基础套餐，未上线免费、上线 15 天后开始计）+ AI 数图（一张几分钱以内，几百张一个月也就几块钱）。
- 工人换微信：让他在新微信上重新扫码填名，你在「工人管理」把旧号停用即可。

## 五、正式发布指引（工人超过 10 人时走这条）

体验版上限 = **10 个体验成员**（微信对个人主体的限制）。人多了就走正式发布，发布后**任何人扫码即用、没有人数限制**。

**发布前要先配两样（都在 mp.weixin.qq.com 后台）：**

1. **服务类目**：设置 → 基本设置 → 服务类目 → 添加「工具」大类（选一个贴合的，如「效率」；个体/个人主体以后台实际可选项为准）
2. **用户隐私保护指引**：设置 → 服务内容声明 → 用户隐私保护指引。按实际使用勾选：
   - **摄像头**：勾「使用」，用途填「拍摄计件报工照片，用于产量记录与核对」
   - 相册/位置/手机号/微信昵称头像等：本程序**不使用**，选不使用
   - 用户填写的信息（姓名）：用于报工对账（如模板有对应项就注明）

**提交审核 + 发布：**

3. 微信开发者工具点「上传」（已传好最新版），或直接用后台已有的开发版本
4. mp.weixin.qq.com → 版本管理 → 开发版本 → **提交审核**（版本说明照实写，如「内部计件报工工具：工人拍照登记产量、店主查看汇总」）
5. 审核一般 1~7 天（工具类通常 1~2 天，有时几小时）；期间体验版照常可用，不影响工人干活
6. 通过后 → 版本管理 → 审核版本 → **发布**
7. 发布后：下载**正式版小程序码**打印贴到工位/发群里，工人扫码直接开用

**发布后注意：**

- 以后**前端页面改动**（界面/流程）每次都要重新提审；但**云函数和数据库的调整即时生效、不用审核**（比如改单价、开/关 AI、改阈值——这些都属于后者，随时可以动）
- 审核被拒常见原因：类目选错 / 隐私指引没配 / 功能不完整——遇到截屏发我，我帮你对着改

## 六、技术备注（给以后的 AI / 开发者看）

- **集合与字段**（金额全部以「分」存整数，字段带 `_c` 后缀；5 个集合全部由 `admin.claim` 首次初始化时自动 `createCollection`，无需手工建）：
  - `wl_users`: openid, name, active, cts, uts
  - `wl_processes`: name, price_c, active, cts
  - `wl_reports`: openid, worker_name, process_id, process_name, item_name(选填的手工品名称), price_c, qty, amount_c, photo(云存储fileID), date(YYYY-MM-DD 东八), ts(毫秒), ai_status(off/pending/done/error), ai_count, ai_votes, ai_flag, review(none/ok/follow)
  - `wl_summary`: _id=日期, workers[], total_qty, total_c, gen_ts
  - `wl_products`: name, active, cts（报工第二步下拉选项，管理员维护）
  - `wl_config`: _id=main, admin_openids[], admin_pass, ai{}
  - `wl_aicounts`: 单张即时数数的临时缓存（_id=`ai_`+md5(照片fileID)；提交时服务端取用后即删，防伪造）
- **云函数与 action**：
  - `login`：无参数 → {openid, role: admin|worker|guest|blocked, name}
  - `report`: action=home|setName|submit|mine（默认 home）
  - `admin`: action=claim|processList|processSave|workerList|workerSave|dailyGet|dayDetail|reviewList|reviewMark|reportDelete|productList|productSave|productDelete（除 claim 外校验 admin_openids；**claim 在无 wl_config 时=首次初始化**：用本次口令建档 + 自动建集合）
  - `countPhoto`: `{fileID}` = 单张即时数数（返回 count，结果写缓存供提交取用）；`{batch=5}` = 批量补数；定时 `0 */5 * * * * *`
  - `summarize`: {date?}；定时 `0 58 23 * * * *`
- **部署**：云函数可用 CLI 一键部署（`cli cloud functions deploy`）；云环境创建 CLI 不支持（`cli cloud env` 只有 list），需在开发者工具 GUI 或云开发控制台开通。
- **触发器维护**：CLI/API 创建的定时触发器**不会显示**在控制台「定时触发器」面板里（该面板只登记 GUI 创建的）。真实判断：① `countPhoto` 日志每 5 分钟自动一条；② 心跳字段 `wl_config.cp_hb`（毫秒时间戳）+ `cp_hb_src`（触发来源，`timer`=定时器）。重建：以管理员身份调用 `makeTriggers`（一次一个：`{"name":"wlCountPhotoTimer"}`、`{"name":"wlSummarizeTimer"}`；报"已经存在"说明还活着）。原理：云函数运行时自带腾讯云临时凭证，直调 SCF（v2018-04-16）的 CreateTrigger，TriggerDesc 填裸 cron，Namespace 用 `SCF_NAMESPACE`（=环境 ID）。
- **前端自动化**：`cli open` → `cli auto --auto-port 9420` → `miniprogram-automator`（ws://127.0.0.1:9420）连接后驱动页面；端口掉了就重跑 `cli auto`。
- **角色路由**：`pages/index/index.js` onLoad → `checkWorklogRole()`（非 admin 则 reLaunch 到报工首页；异常静默保持）。**改这段前先想清楚，它保护算价页不给工人看。**
- **拍照**：`wx.chooseMedia({sourceType:['camera'], sizeType:['compressed']})`，上传路径 `wl_reports/YYYYMMDD/时间戳-随机.jpg`。
- **AI 提示词**在 `countPhoto/index.js` 顶部 `PROMPT`——**不要**把工人报的数量拼进提示词（会让模型直接复读报数，锚定污染）。
- 日期/时间一律自己按 `+8h` 换算（云函数时区是 UTC），见各函数顶部 `TZ`。
